# Code Review: Security Review

**Date:** 2026-04-24

## Summary
The codebase shows clear awareness of XSS — `escapeHtml` is used extensively across `app.js` and modal/plugin renderers — but there are **three serious XSS holes where AI-generated content flows into `innerHTML` through a naïve `renderMarkdown()` helper that does not escape HTML before applying its regex substitutions**. Any AI response (handoff summary, RIS content, completion summary) containing raw `<script>` or event-handler attributes is executed in the renderer. On the main process side, `path.join` is used on renderer-supplied filenames without traversal validation in `plan:saveToDocs`, and the static webserver's traversal protection (strip leading `../` only) is weaker than a `resolve + startsWith(root)` check. Shell/argument injection is mostly well-contained (`spawn` uses argv arrays), though `git:checkout` passes an unvalidated branch name that could be mistaken for a flag. Database queries use parameterized bindings throughout.

## Findings

- **[CRITICAL]** XSS_RENDER_MARKDOWN_UNESCAPED src/renderer/app.js:5505 — `renderMarkdown()` applies regex substitutions without first escaping `&<>` in the input; raw HTML in AI content passes through to innerHTML callers (root cause of the three XSS findings below).
- **[CRITICAL]** XSS_AI_IN_INNERHTML src/renderer/app.js:2031 — `summaryDisplay.innerHTML = ...renderMarkdown(data.summary)...` — AI-generated handoff summary fed directly to `renderMarkdown` and then `innerHTML` without escaping.
- **[CRITICAL]** XSS_AI_IN_INNERHTML src/renderer/app.js:5392 — Same pattern as above on the generate-summary path: `summaryDisplay.innerHTML = ...renderMarkdown(response.response)...`.
- **[CRITICAL]** XSS_AI_IN_INNERHTML src/renderer/lib/modal-manager.js:3265 — RIS viewer sets `content.innerHTML = ...renderMarkdown(risContent)...` where `risContent` is AI-generated markdown read from the DB; `renderMarkdown` here (lines 2008-2044) also omits the pre-escape step.
- **[IMPORTANT]** PATH_TRAVERSAL_IPC src/main/ipc-handlers.js:3524 — `plan:saveToDocs` does `const dest = path.join(docsDir, filename); fs.writeFileSync(dest, content, 'utf8')` where `filename` arrives from the renderer. `path.join(docsDir, '../../outside.md')` still escapes `docsDir`; no `path.resolve(dest).startsWith(path.resolve(docsDir))` guard is performed (unlike the `validateFilename` helper used for GUI designs at puffin-state.js:3779).
- **[IMPORTANT]** WEAK_PATH_TRAVERSAL_GUARD src/main/website-server.js:285 — The traversal defense is only `path.normalize(urlPath).replace(/^(\.\.(\/|\\|$))+/, '')` which strips *leading* `..` segments; `filePath` is then served without a final `resolve + startsWith(serveRoot)` check. Combined with URL decoding it is fragile.
- **[IMPORTANT]** ARG_INJECTION_GIT src/main/git-service.js:382 — `execGit(['checkout', name])` accepts `name` from the `git:checkout` IPC without validation; values beginning with `-` (e.g. `--detach`, `-q`) are parsed as flags by git. `createBranch` validates via `validateBranchName`, but `checkout` does not.
- **[IMPORTANT]** XSS_EXTERNAL_DATA_IN_INNERHTML src/renderer/app.js:894 — `<option value="${m.id}"...>${m.name} — ${m.description}</option>` is built from Ollama API data and assigned via `innerHTML` at line 899 without escaping. Requires a malicious/compromised Ollama server but there is no defence in depth.
- **[IMPORTANT]** XSS_INNERHTML_PLUS_EQUALS plugins/designer-plugin.disabled/renderer/components/DesignerView.js:327 — `el.innerHTML += ...` used to append resize handles. Content is a static template in this case, but the plugin (though `.disabled`) is still present in the source tree and violates the rule.
- **[INFO]** EXEC_SHELL_INTERPOLATION src/main/claude-service.js:164 — `exec(\`taskkill /pid ${proc.pid} /T /F\`)` interpolates a variable into a shell string. `proc.pid` is always numeric so it is not exploitable today, but the pattern is discouraged; prefer `execFile('taskkill', ['/pid', String(proc.pid), '/T', '/F'])`.
- **[INFO]** EXEC_SHELL_INTERPOLATION src/main/vibe-service.js:174 — Same pattern as above: `exec(\`taskkill /pid ${this.currentProcess.pid} /T /F\`)`.
- **[INFO]** XSS_ATTR_UNESCAPED plugins/code-review-plugin/renderer/components/ReviewViewer.js:70 — `data-id="${item.id}"` and `:${item.line}` at line 73 are interpolated into `innerHTML` without passing through `this._esc(...)`, inconsistent with sibling fields on the same element.
- **[INFO]** SHELL_OPEN_EXTERNAL_UNVALIDATED src/main/ipc-handlers.js:2732 — `shell:openExternal` forwards any renderer-provided URL to `shell.openExternal(url)` with no scheme allow-list; a compromised renderer could open `file://`, `javascript:`, or other local-handler URLs.
