# Code Review: SAM State Management Review

**Date:** 2026-04-24

## Summary

Inspected SAM pattern compliance across `src/renderer/sam/`, `src/renderer/lib/state-persistence.js`, `src/renderer/app.js`, and the main-process database repositories. Found three direct mutations of SAM state outside of acceptors (all mutating `model.userStories[i].inspectionAssertions` or sprint-story fields through the transient `state` reference returned by `computeState`, which aliases model arrays). Found a persistAction whitelist/handler-block mismatch that makes the entire orchestration / code-review / bug-fix sprint persistence branch dead code (early-returns at line 138 before reaching the handler at line 267), plus several whitelist entries with no matching handler block. Also flagged two `setTimeout` call sites that dispatch SAM intents (`showSprintCloseModal`) without re-validating that the sprint is still active. INSERT call sites for `plans`, `ris`, `inspection_assertions`, and `completion_summaries` now use internally-generated UUIDs (the previously-documented IA001 collision bug is fixed), so no new ID-collision finding.

## Findings

- **[CRITICAL]** DIRECT_MUTATION src/renderer/lib/state-persistence.js:239 — `state.userStories[index].inspectionAssertions = result.story.inspectionAssertions` mutates the SAM model via the aliased `state.userStories` (see `computeState` returning `model.userStories || []` in `src/renderer/sam/state.js:36`). Must dispatch an action (e.g. `UPDATE_USER_STORY`) so the acceptor applies the change. Confidence 95.
- **[CRITICAL]** DIRECT_MUTATION src/renderer/lib/state-persistence.js:605 — `state.userStories[index].inspectionAssertions = updatedStory.inspectionAssertions` mutates the model directly in the `ADD_STORIES_TO_BACKLOG` handler after the auto-assertion IPC result. Same root cause as above; should go through an intent. Confidence 95.
- **[CRITICAL]** DIRECT_MUTATION src/renderer/app.js:6326 — `sprintStory.inspectionAssertions = freshStory.inspectionAssertions` inside `handleCreApproval`'s post-approval refresh mutates `this.state.activeSprint.stories[i]` (which aliases `model.activeSprint.stories`). Should be dispatched via `updateSprintStoryAssertions`/`updateUserStory` (as is already done on line 6290–6291), not patched in place. Confidence 92.
- **[CRITICAL]** WHITELIST_HANDLER_MISMATCH src/renderer/lib/state-persistence.js:267 — The sprint-persistence handler block at lines 267–281 lists `SELECT_IMPLEMENTATION_MODE`, `START_AUTOMATED_IMPLEMENTATION`, `ORCHESTRATION_STORY_STARTED`, `ORCHESTRATION_STORY_COMPLETED`, `UPDATE_ORCHESTRATION_PHASE`, `PAUSE_ORCHESTRATION`, `RESUME_ORCHESTRATION`, `STOP_ORCHESTRATION`, `START_CODE_REVIEW`, `ADD_CODE_REVIEW_FINDING`, `SET_CODE_REVIEW_FINDINGS`, `COMPLETE_CODE_REVIEW`, `UPDATE_FINDING_STATUS`, `START_BUG_FIX_PHASE`, `START_FIXING_FINDING`, `COMPLETE_FIXING_FINDING`, `COMPLETE_BUG_FIX_PHASE` — none of these appear in the `persistActions` whitelist at lines 111–136. Any of these actions hit the early-return at line 138, so the handler is dead code and orchestration/code-review/bug-fix state is never persisted. Confidence 98.
- **[IMPORTANT]** WHITELIST_HANDLER_MISMATCH src/renderer/lib/state-persistence.js:122 — `ITERATE_SPRINT_PLAN` is whitelisted but has no matching branch in any handler block; persist() logs "persisted" but writes nothing. Confidence 88.
- **[IMPORTANT]** WHITELIST_HANDLER_MISMATCH src/renderer/lib/state-persistence.js:116 — `ADD_GUI_ELEMENT`, `UPDATE_GUI_ELEMENT`, `DELETE_GUI_ELEMENT`, `MOVE_GUI_ELEMENT`, `RESIZE_GUI_ELEMENT`, `CLEAR_GUI_CANVAS` are whitelisted but no handler branch exists; GUI-canvas changes are silently not persisted. Confidence 88.
- **[IMPORTANT]** WHITELIST_HANDLER_MISMATCH src/renderer/lib/state-persistence.js:133 — `MARK_STORY_READY`, `UNMARK_STORY_READY`, `UPDATE_DERIVED_STORY`, `DELETE_DERIVED_STORY` are whitelisted (comment says "trigger generation tracking persistence") but neither the user-story block (205) nor the story-gen block (716–722) matches them; persist() is a no-op. Confidence 85.
- **[IMPORTANT]** TIMER_NO_STATE_CHECK src/renderer/app.js:7485 — `setTimeout(() => this.intents.showSprintCloseModal(), 1500)` dispatches a SAM intent 1.5 s later with no guard that `this.state.activeSprint` still exists or that orchestration is still running; if the user closes the project or stops orchestration in the interval, the modal opens against invalid state. Compare the same call path at line 7472 which does re-check `orchestration.status`. Confidence 82.
- **[IMPORTANT]** TIMER_NO_STATE_CHECK src/renderer/app.js:7722 — Same pattern: `setTimeout(() => this.intents.showSprintCloseModal(), 1500)` at the end of the bug-fix completion flow dispatches the intent unconditionally without a status/sprint validity check. Confidence 82.
- **[INFO]** TIMER_NO_STATE_CHECK src/renderer/app.js:6932 — `setTimeout(() => { window.puffin.claude.submit({ ... project: this.state.config ? {...} : null }) }, 500)` reads `this.state` inside the timer and fires an IPC submit; it does not re-check `orchestration.status` before submitting, so a pause/stop issued in the 500 ms window still results in a continuation prompt being sent. Not strictly a SAM dispatch, but it re-enters the orchestration pipeline whose next step *is* a SAM dispatch. Confidence 78.
