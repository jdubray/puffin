# Code Review: Aggregate and Publish Nightly Review Report

**Date:** 2026-04-24

## Summary
The `ReviewRunner` implements parallel execution (`Promise.all`) and emits a toast notification on completion, satisfying two of the six acceptance criteria. However, three core requirements are entirely missing: no aggregated `docs/review-summary-YYYY-MM-DD.md` is ever written, no dry-run mode exists (the runner always calls `fs.writeFileSync`), and nothing gates sprint completion on "zero critical findings". As a consequence, the "critical issues listed individually in the summary" criterion is also unmet because the summary file itself is absent.

## Findings

- **[CRITICAL]** MISSING_SUMMARY_REPORT plugins/code-review-plugin/lib/review-runner.js:50 — `run()` returns a `Map` of per-story results but never writes an aggregated `docs/review-summary-YYYY-MM-DD.md` with total finding counts by severity; the acceptance criterion requires this consolidated report to be produced at the end of the run.
- **[CRITICAL]** MISSING_DRY_RUN_MODE plugins/code-review-plugin/lib/review-runner.js:26 — `ReviewRunner.run(runId, stories)` accepts no `dryRun`/`options` parameter and unconditionally calls `fs.writeFileSync(reportPath, markdown, ...)` at line 58; the acceptance criterion requires a dry-run mode that returns findings without writing files.
- **[CRITICAL]** MISSING_CRITICAL_FINDINGS_LIST plugins/code-review-plugin/lib/review-runner.js:158 — `_countFindings()` only returns severity tallies (`{ critical, important, info }`) and discards the parsed finding objects (file, line, description); the summary must list each critical finding individually with file + line, which is impossible with only counts.
- **[CRITICAL]** MISSING_SPRINT_COMPLETION_GATE plugins/code-review-plugin/lib/review-runner.js:50 — no code in the plugin (runner, IPC handlers, or renderer) checks `totalCritical === 0` before marking the sprint complete; a grep for `markComplete`/`closeSprint`/critical-gate logic returns zero matches in the review plugin. The acceptance criterion "Sprint is marked complete only if zero critical findings exist" is unenforced.
- **[IMPORTANT]** UNCONDITIONAL_ERROR_FILE_WRITE plugins/code-review-plugin/lib/review-runner.js:40 — the error branch of `run()` also calls `fs.writeFileSync(reportPath, errMsg, 'utf-8')` unconditionally, so adding dry-run later will require guarding both the success path (line 58) and this error path; currently dry-run cannot be a pure in-memory operation.
- **[IMPORTANT]** FINDINGS_NOT_COLLECTED_FOR_AGGREGATION plugins/code-review-plugin/lib/review-runner.js:59 — `_runStory()` returns only `{ findingCount, reportPath }`; it does not return the parsed finding list from `finding-parser.js`, so even if a summary writer were added it could not access per-finding file/line/description needed for the "critical issues listed individually" requirement.
- **[IMPORTANT]** TOAST_IS_RENDERER_ONLY plugins/code-review-plugin/renderer/components/CodeReviewView.js:170 — the completion toast fires from the renderer poll loop only when the `CodeReviewView` is mounted and polling; a nightly/background run without the view open would never fire the toast, so the "toast fires when the run completes" criterion is not reliably satisfied for headless nightly execution.
- **[INFO]** UNUSED_CONSTRUCTOR_PARAM plugins/code-review-plugin/lib/review-runner.js:13 — `constructor(projectPath, outputDir, _unused)` reserves a third positional slot "for future progress channel"; adding dry-run/options should go through a proper options object rather than another positional parameter to avoid compounding this pattern.
