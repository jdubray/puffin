# Code Review: UI Components Review

**Date:** 2026-04-24

## Summary
Audit identified two classes of active violations: several modal stylesheet blocks still set width directly on `.modal.classname` instead of the documented `.modal:has(.classname)` override pattern, and several assertion-rendering UI paths read from the in-memory sprint story's `inspectionAssertions` without falling back to the backlog/DB copy — a known source of "0 assertions" display regressions when sprint and backlog arrays fall out of sync. No `=== "implemented"` status comparisons were found, and the `risMap` feature-visibility call site now has an async DB fallback (`listRisStoryIds`), so that finding is downgraded to informational. The existing assertion count sites in app.js (lines 751–753, 3160–3163) correctly use `.length > 0` fallback and serve as the reference pattern.

## Findings

- **[IMPORTANT]** MODAL_WIDTH_IN_COMPONENT_STYLESHEET src/renderer/styles/components.css:9360 — `.modal.story-review-modal { min-width: 600px; max-width: 800px }` sets width directly on `.modal` via class-chaining instead of the documented `.modal:has(.story-review-modal)` override pattern used elsewhere in this file.
- **[IMPORTANT]** MODAL_WIDTH_IN_COMPONENT_STYLESHEET src/renderer/styles/components.css:10174 — `.modal.handoff-modal { min-width: 550px; max-width: 700px }` sets width directly on `.modal` via class-chaining; should use `.modal:has(.handoff-modal)` for consistency and to work with the modal-manager's type-routed DOM structure.
- **[IMPORTANT]** ASSERTION_DISPLAY_NO_DB_FALLBACK src/renderer/components/user-stories/user-stories.js:1891 — `renderInspectionAssertions(story)` reads `story.inspectionAssertions || []` and returns `''` when length is 0, with no fallback to the DB-sourced backlog copy; empty in-memory sprint story silently suppresses the assertions section.
- **[IMPORTANT]** ASSERTION_DISPLAY_NO_DB_FALLBACK src/renderer/components/user-stories/user-stories.js:1658 — `evaluationProgress` total is seeded from `story.inspectionAssertions?.length || 0` with no backlog/DB fallback; if sprint story's array is empty but DB has entries, progress bar reports `0 / 0`.
- **[IMPORTANT]** ASSERTION_DISPLAY_NO_DB_FALLBACK src/renderer/lib/modal-manager.js:3864 — `renderAssertionStatusBadge(story)` reads only `story.inspectionAssertions || []` and returns `''` on empty; badge disappears when sprint/backlog are desynchronized.
- **[IMPORTANT]** ASSERTION_DISPLAY_NO_DB_FALLBACK src/renderer/lib/modal-manager.js:3902 — `renderAssertionSummary(story)` has the same single-source read; should prefer whichever of sprint/backlog has `length > 0` (mirroring app.js:3160–3163).
- **[IMPORTANT]** ASSERTION_DISPLAY_NO_DB_FALLBACK src/renderer/lib/modal-manager.js:4229 — Assertion detail modal reads only `story.inspectionAssertions || []`; `total = assertions.length` will display 0 even when DB/backlog has assertions.
- **[IMPORTANT]** ASSERTION_DISPLAY_NO_DB_FALLBACK src/renderer/lib/modal-manager.js:2827 — Assertion failures modal uses `story.inspectionAssertions || []` to build the assertion lookup map; failed results whose IDs live only in the backlog copy will render as blank rows (`if (!assertion) return ''`).
- **[INFO]** RISMAP_FEATURE_VISIBILITY src/renderer/components/user-stories/user-stories.js:429 — `this.risAvailable` is seeded from `state.activeSprint?.risMap` to drive RIS-button visibility; `risMap` is ephemeral (no DB column) so first render after restart shows no RIS buttons. A DB fallback via `listRisStoryIds()` runs asynchronously on lines 434–446, which mitigates but does not eliminate the flash; prefer gating button visibility on the DB-backed set from the start.
- **[INFO]** TRUTHY_ARRAY_CHECK — No active violations found. All surveyed call sites use either `|| []` (fallback assignment) followed by `.length` checks, or explicit `.length > 0` / `.length === 0` guards (e.g., app.js:751–753, app.js:3160–3163, app.js:4773–4775, app.js:6325, modal-manager.js:3868, 3906). Reference pattern is consistent across renderer.
- **[INFO]** STORY_STATUS_IMPLEMENTED — No violations found. All story status comparisons use `=== 'completed'` (app.js:3108–3109, 3131–3132, 4234, 4742, 5686, 5740; sam/state.js:470, 499, 523, 536; sam/model.js:3308). No `=== 'implemented'` comparisons exist.
